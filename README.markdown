SlackHacks -- Essential Quality of Life Tweaks to Native Blizzard UIs
=====================================================================

This is *yet another* "Quality of Life" WoW addon with various small features and tweaks, but my focus is on making my changes look like they're part of the native Blizzard UI.

Everything is a module.

Everything is optional.

Everything is off by default. (Please read all the options!)

If you've used Plumber or Leatrix, this is similar, but I'm trying *very* hard to make it look like Blizzard wrote all the features I'm providing. (Because of this, it is probably incompatible with full UI redesigns like Ellesmere UI.) 

## Why make this? Why make another QoL addon...?

I've been programming in general since 1998, and *professionally* for almost 20 years, and right now, I'm sorely depressed at seeing how all the "new" addons are slopified junk generated by Claude, or how many existing addons have turned buggy and are now eating CPU because developers have given up on quality.

Am I using Copilot for some of it? *Yes.* But I'm using my years of experience to make sure it's good output, and once I finish any given module, I spend time *manually* reviewing and polishing it. As soon as I'm done with all the features, and before I release this into the public CurseForge page, I will review ***all*** the code and make sure all of it is to the quality I would *professionally* feel confident and proud of releasing.

I get *why* we're all using Copilot today: Blizzard has documented nothing and it's a struggle to make even the most "simple" sounding things. But if you're using Claude and "vibing" your addons 100%, you should be embarrassed.

## Build and release configuration

Shared, non-secret build and release defaults live in
[`scripts/defaults.env`](./scripts/defaults.env), so a fresh clone can build
without any local configuration. For local overrides and credentials, create an
ignored `.env` in the repository root by copying
[`.env.example`](./.env.example) and replacing the placeholder values with each
developer's own deployment tokens. For example, run `cp .env.example .env` from
the repository root in Bash.

Do not commit `.env` or put API tokens in `scripts/defaults.env`. The deployment
scripts also support Proton Pass; set the appropriate `PROTON_PASS_ITEM_*`
values in `.env` if your item names differ from the defaults. Environment
variables already set by the shell or CI/CD environment take precedence over
both files, so CI can inject its own configuration and secrets.
